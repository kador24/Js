# Jamal Phone Manager

تطبيق Android لإدارة متجر متعدد المنتجات، مصمم ليعمل **Offline-first** ويخزن البيانات الأساسية محليًا في SQLite.

## ما الذي يديره التطبيق؟

- المنتجات والتصنيفات والباركود والصور والضمان والخصائص.
- المخزون عبر **سجل حركات** وليس تعديل كمية صامت.
- المشتريات مع تحديث التكلفة بمتوسط مرجح.
- المبيعات متعددة المنتجات مع خصم وربح محفوظ حسب تكلفة المنتج وقت البيع.
- المرتجعات مع الاحتفاظ بالفاتورة الأصلية وتسجيل حركة المخزون ورد الأموال.
- المبيعات الآجلة والدفعات والتحصيل والذمم.
- المصاريف مع إلغاء منطقي (`voided`) للحفاظ على التاريخ.
- رأس المال: رأس مال أولي + مساهمات + سحوبات.
- لوحة تحكم وتقارير ومؤشرات السيولة والمخزون والذمم.
- مسح الباركود بالكاميرا وإدخال يدوي.
- بحث خارجي مساعد للباركود عبر Open Food Facts عند توفر الإنترنت؛ لا يُفترض أنه قاعدة مواصفات كاملة للهواتف.
- نسخ احتياطية محلية مشفرة AES-GCM تشمل SQLite وصور المنتجات.
- مفتاح استعادة منفصل، مع الاحتفاظ بآخر 5 نسخ محلية.
- Telegram اختياري لإرسال النسخة والتقرير.
- حفظ Bot Token وChat ID في Android Secure Storage بدل SQLite.
- جدولة Android في الخلفية أسبوعية أو شهرية باستخدام WorkManager عند توفر الشبكة.
- واجهة عربية RTL مع الوضع الفاتح والداكن.

## المحاسبة المهمة

### الربح

ربح السطر = `(سعر البيع - تكلفة الوحدة المحفوظة وقت البيع) × الكمية`.
الخصم على الفاتورة يقلل الربح الإجمالي للفواتير المكتملة.

### المخزون

كل تغيير يترك أثرًا في `stock_movements`:

- `opening` رصيد افتتاحي.
- `in` دخول بسبب شراء.
- `out` خروج بسبب بيع.
- `return` إرجاع بيع.
- `adjust` تسوية يدوية.

### البيع الآجل

الدفعة عند إنشاء الفاتورة تسجل كتحصيل، وأي دفعة لاحقة تسجل في `receivable_payments`.
عند الإرجاع الكامل تُسجل عملية `refund` وتُستبعد الفاتورة من مؤشرات المبيعات والذمم.

## النسخ الاحتياطي

النسخة `.jpm` مشفرة محليًا باستخدام مفتاح 256-bit مخزن في Android Secure Storage.
النسخة تشمل:

- قاعدة SQLite.
- صور المنتجات الموجودة داخل مجلد التطبيق.

مفتاح الاستعادة **ضروري** لاستعادة نسخة مشفرة على جهاز آخر. احتفظ به خارج الهاتف.

## Telegram

Telegram اختياري. عند ضبط Bot Token وChat ID:

- النسخة المجدولة تُنشأ محليًا أولًا.
- إذا توفر الإنترنت تُرسل النسخة مع التقرير.
- إذا تعذر الإرسال تبقى النسخة محليًا ويُحفظ الإخفاق.
- الرسائل/المهام الفاشلة يمكن أن تدخل طابورًا لإعادة المحاولة.

**لا تضع أي Bot Token أو Chat ID داخل GitHub أو الكود المصدر.**

## الباركود

الماسح يقرأ الباركود ويبحث أولًا داخل منتجات المتجر. يوجد أيضًا بحث خارجي مساعد عند الضغط على البحث الخارجي.
إذا لم توجد نتيجة، يبقى الإدخال اليدوي متاحًا.

## ملاحظة مهمة حول APK Release

الإصدار الحالي يستخدم `signingConfigs.debug` في Release لتسهيل الاختبار والتثبيت. هذا مناسب للاختبار الشخصي، لكنه ليس توقيع متجر Google Play. للنشر التجاري نحتاج Keystore خاص وتوقيع Release حقيقي.

## الاختبار الوظيفي المقترح قبل الاستخدام التجاري

جرّب السيناريو التالي:

1. رأس مال أولي: 3,000,000 دج.
2. شراء 10 وحدات بتكلفة 180,000 دج.
3. بيع 3 وحدات بسعر 215,000 دج.
4. إرجاع فاتورة البيع.
5. تسجيل مصروف.
6. إنشاء بيع آجل مع دفعة أولى.
7. تسجيل تحصيل لاحق.
8. إنشاء نسخة `.jpm`.
9. استعادة النسخة والتحقق من المنتجات والصور والمخزون.
10. ضبط Telegram وتجربة الإرسال يدويًا ثم التحقق من الجدولة.
